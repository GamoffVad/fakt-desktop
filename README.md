# FAKT

**FAKT** — настольное приложение для Windows (WPF, .NET Framework 4.8) для поиска лиц и связанных с ними фактов в табличных файлах.

Приложение делает следующее:

1. Рекурсивно находит файлы в выбранной папке.
2. По первым пяти строкам каждого текстового файла с помощью выбранной LLM определяет табличную структуру: CSV, TSV, TXT с разделителем или фиксированной шириной, XML, JSON Lines, JSON-массив.
3. Проверяет эту структуру парсером.
4. Потоково читает записи через Python/Pandas.
5. Передаёт каждую запись модели, чтобы выделить лиц и факты.
6. Сохраняет результат в существующую базу SQL Server 2025. Фамилия, имя, отчество, дата и место рождения записываются в отдельные поля, остальные факты — в JSON-поле `[ALL]`.
7. Даёт полнотекстовый и точный поиск по сохранённым сведениям и исходным файлам.

Приложение работает только с файлами выбранного источника. Оно не собирает сведения из внешних источников, не обогащает данные автоматически и не удаляет и не перемещает исходные файлы.

> **Статус: в активной разработке.** Проект создаётся поэтапно по заданию [`APP_DEVELOPMENT_PROMPT.md`](APP_DEVELOPMENT_PROMPT.md). Готовые части и проверки перечислены ниже. Непроверенное прямо помечено как непроверенное.

## Возможности

- **Обработка.** Выбор папки, потоковое рекурсивное сканирование и таблица файлов со статусами. Учитываются длинные пути, недоступные папки и junction; переход по junction по умолчанию выключен. Анализ структуры идёт по пяти строкам с признаком усечения образца. Есть пауза, продолжение и остановка без дубликатов.
- **Извлечение.** Записи отправляются в LLM пакетами с устойчивыми `source_row_id`. Ответ проверяется: не должно быть неизвестных, повторяющихся или пропущенных записей. Каждое значение сверяется с исходной записью. Неоднозначные даты не угадываются, а к телефонам не добавляется код страны.
- **Хранение.** Две основные таблицы: `SourceFiles` с кодом файла `T_` и 18 случайными цифрами и `PersonFacts`. Дополнительные поля и объекты вводятся явными миграциями, существующие таблицы не пересоздаются. Запись идемпотентна: результат фиксируется атомарно вместе с checkpoint.
- **Поиск.** Режимы: все слова, любое слово, точная фраза, подстрока. Есть фильтры по ФИО, дате, месту рождения, типу факта, нормализованному телефону или счёту, файлу и ID, а также серверная пагинация. По щелчку на результате открывается всплывающая карточка со всеми сведениями, включая все факты из `[ALL]`.
- **Провайдеры LLM.**
  - Облачные: OpenAI, **OpenAI Compatible**, Azure OpenAI, Anthropic, Google Gemini, Mistral, DeepSeek, Qwen (Alibaba Cloud Model Studio), xAI, Groq, OpenRouter, Together AI, Fireworks AI.
  - Локальные серверы: Ollama, LM Studio.
  - Список моделей загружается из API. Возможности модели проверяются тестовым запросом.
- **Безопасность.**
  - Роли «Администратор» и «Оператор» привязаны к пользователям и группам Windows.
  - Ключи и пароли хранятся через DPAPI.
  - Журнал не содержит секретов и полных персональных данных.
  - Содержимое файлов передаётся модели как данные, а не как инструкции.

## Архитектура

```text
Fakt.sln
src/
  Fakt.Core/            модели, контракты, правила проверки, промпты и JSON Schema
  Fakt.Application/     конвейер обработки, повторы и лимиты LLM, прикладные сервисы
  Fakt.Infrastructure/  SQL (System.Data.SqlClient), адаптеры LLM, IPC с worker, DPAPI, сканер
  Fakt.Desktop/         WPF, MVVM, тема Arctic Blue
worker/                 Python worker: определение кодировки, образец, проверка структуры, Pandas-чтение
database/               SQL-миграции и поисковые объекты
testdata/               синтетические тестовые файлы с эталонными ответами
tools/                  генератор тестовых данных, нагрузочный тест
docs/                   COMPATIBILITY, SETUP, ARCHITECTURE, PROVIDERS, TEST_REPORT
```

Конвейер ограничен по памяти: чтение (chunk Pandas) → очередь LLM (пакеты по числу записей и токенам) → проверка → очередь SQL → фиксация checkpoint. Все очереди имеют предел. Когда очередь заполнена, чтение замедляется.

Обмен WPF-клиента с Python worker идёт версионированными JSON-сообщениями через stdin/stdout, диагностика worker — через stderr. Протокол описан в [`worker/protocol/PROTOCOL.md`](worker/protocol/PROTOCOL.md).

## Совместимость

Клиент рассчитан на **Windows 7 SP1 x64**, **.NET Framework 4.8** и **Python 3.8.10** (поставляемая embeddable-сборка с закреплёнными pandas 2.0.3 и numpy 1.23.5). SQL Server 2025 работает на отдельной поддерживаемой серверной ОС.

Windows 7 и ветка Python 3.8 вне поддержки безопасности. Точные версии, статусы проверки и известные ограничения описаны в [`docs/COMPATIBILITY.md`](docs/COMPATIBILITY.md): TLS 1.2, шифронаборы, `Encrypt=Strict`, DeepSeek.

## Сборка

Нужен .NET SDK 8 или новее (проверено на 10.0.302), сборка идёт под `net48`:

```bash
dotnet build Fakt.sln -c Release
```

Сборка поставляемого worker (Python 3.8.10 embeddable и колёса по хешам) и установочного пакета будет описана в `docs/SETUP.md`.

## Тестовые данные

В [`testdata/`](testdata/README.md) лежат 54 синтетических файла разных типов: структурированные, неструктурированные, пограничные, двоичные и проверки безопасности XML. Для структурированных есть эталонные ответы. Все данные вымышлены. Набор создаётся детерминированно:

```bash
python tools/testdata/generate_testdata.py
```
