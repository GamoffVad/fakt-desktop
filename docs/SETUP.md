# Установка и настройка FAKT

FAKT — настольное приложение Windows: находит файлы в папке, определяет их табличную структуру по первым строкам, читает записи Python-worker'ом (pandas), извлекает лица и факты с помощью выбранной LLM и сохраняет их в SQL Server, где по ним работает поиск.

**Приложению не нужен интернет.** Всё необходимое поставляется в папке программы: клиент .NET, Python 3.8 с библиотеками и код worker. База данных — ваш SQL Server. Модель может быть локальной (LM Studio, Ollama или любой OpenAI-совместимый сервер в вашей сети). Облачные провайдеры подключаются только по явной настройке администратора, и тогда записи файлов уходят этому провайдеру.

## 1. Требования

| Компонент | Требование |
|---|---|
| ОС клиента | Windows 7 SP1 x64 (целевая, **проверка на ней не выполнялась**), Windows 10/11 x64 |
| .NET Framework | **4.8** (не 4.8.1 — он не устанавливается на Windows 7) |
| SQL Server | 2025 (17.x) с компонентом Full-Text Search, на Windows 10+ или Windows Server 2019+; локально или в сети |
| LLM | локальный сервер (LM Studio, Ollama, OpenAI-совместимый) или облачный провайдер — см. `docs/PROVIDERS.md` |
| Экран | от 1024 × 720 DIP, базовый макет 1440 × 900 |

SQL Server 2025 на Windows 7 не устанавливается: клиент на Windows 7 подключается к серверу на другой машине.

## 2. Подготовка Windows 7 SP1 x64 (без интернета)

Все пакеты скачиваются заранее на другом компьютере (Microsoft Update Catalog) и переносятся на целевую машину.

1. **Обновления стека обслуживания и SHA-2**: KB4490628, затем KB4474419 — без них не проверяются подписи современных пакетов.
2. **Universal C Runtime**: KB2999226 (или KB3118401). Без него встроенный Python не запускается (нет `api-ms-win-crt-*.dll`).
3. **KB2533623** (или заменяющее его обновление) — загрузка библиотек, нужная встроенному Python.
4. **D3DCompiler_47**: KB4019990 — рекомендуется для WPF.
5. **.NET Framework 4.8**: офлайн-установщик `NDP48-x86-x64-AllOS-ENU.exe` (в списке программ — KB4503548). Корневой сертификат «Microsoft Root Certificate Authority 2011» должен быть установлен.
6. **TLS 1.2 для клиента**: импортируйте `windows7\tls12-client.reg` из папки программы (или отметьте задачу в установщике) и перезагрузите компьютер. Файл включает TLS 1.2 в SChannel (`DisabledByDefault=0`, `Enabled=1`) и задаёт `SystemDefaultTlsVersions`/`SchUseStrongCrypto` для .NET. Без этого не будет работать шифрованное подключение к SQL Server.

Ограничения Windows 7: нет TLS 1.3 и шифронаборов ECDHE-RSA-AES-GCM. Серверы, которые принимают только их (например, DeepSeek API на момент проверки), с Windows 7 напрямую недоступны — используйте шлюз в своей сети (профиль «OpenAI Compatible»).

## 3. Установка FAKT

**Вариант А — переносная папка.** Скопируйте папку `FAKT` (или распакуйте `FAKT-<версия>-win-x64.zip`) в любое место, например `C:\Program Files\FAKT`, и запустите `FAKT.exe`.

**Вариант Б — установщик** `FAKT-<версия>-setup.exe` (Inno Setup): проверяет наличие .NET Framework 4.8, ничего не загружает, на Windows 7 может сразу включить TLS 1.2. *Сценарий установщика написан, но на машине разработки не компилировался — требует проверки.*

Состав папки:

| Путь | Назначение |
|---|---|
| `FAKT.exe`, `*.dll`, `FAKT.exe.config` | клиент (.NET Framework 4.8, x64) |
| `worker\python\` | Python 3.8.10 embeddable x64 с pandas 2.0.3, numpy 1.23.5, defusedxml 0.7.1 (изолированный `python38._pth`) |
| `worker\fakt_worker\`, `worker\fakt_worker_main.py` | код worker |
| `windows7\tls12-client.reg` | включение TLS 1.2 на Windows 7 |
| `docs\` | документация |
| `release-manifest.json` | версии и SHA-256 всех файлов выпуска |

## 4. SQL Server

1. Установите SQL Server 2025 с компонентом **Full-Text Search** (есть во всех редакциях, включая Express).
2. **Шифрование.** Рекомендуется сертификат сервера, которому доверяет клиент (выпущенный вашим ЦС или установленный в доверенные корневые сертификаты клиента). Для тестового сервера с самоподписанным сертификатом в FAKT можно включить «Доверять сертификату сервера без проверки» — приложение покажет предупреждение. Режим `Encrypt=Strict` (TDS 8.0) клиентом не поддерживается: не включайте на сервере Force Strict Encryption.
3. **Учётная запись.** Рекомендуется Windows-аутентификация. Нужные права:
   - для **автоматического создания базы** — роль сервера `dbcreator` (или право `CREATE DATABASE`);
   - для работы с существующей базой — чтение и запись основных таблиц, создание таблиц и индексов для миграций, создание полнотекстового каталога (проще всего — `db_owner` на базе FAKT).
4. **База данных.** Укажите в FAKT имя базы. Если такой базы на сервере нет, FAKT **создаст её автоматически** при сохранении настроек или проверке соединения — сразу со всей схемой (таблицы SourceFiles и PersonFacts, служебные таблицы, индексы, полнотекстовый каталог). Существующая база не изменяется: её схема меняется только явными миграциями на вкладке «База данных» после просмотра SQL. Таблицы и данные не удаляются и не пересоздаются.

## 5. Первый запуск

1. При первом запуске FAKT предлагает назначить **владельца** — текущую учётную запись Windows; она получает роль «Администратор». Можно сразу добавить администраторов и операторов (учётные записи или группы Windows). Паролей по умолчанию нет.
2. **Администрирование → База данных**: укажите сервер и базу (по умолчанию — SQL Server этого компьютера `localhost` и база `FAKT`, вход Windows) → «Сохранить и проверить».
   - Базы нет — она создаётся вместе со всеми таблицами FAKT.
   - База есть (например, рабочая, с вашими таблицами) — FAKT показывает, что будет создано, и после подтверждения создаёт недостающее: таблицы SourceFiles и PersonFacts (если их нет), служебные таблицы, поисковую проекцию и полнотекстовый индекс (если установлен Full-Text Search). В уже существующие SourceFiles/PersonFacts добавляются только недостающие технические столбцы (допускают NULL) и индексы, без которых не работают обработка и поиск; записи, которые там уже есть, индексируются для поиска. Необязательные изменения ваших таблиц (ограничение ISJSON, индексы фильтров) не выполняются автоматически — они доступны в «Тонкой настройке». Таблицы и данные никогда не удаляются и не пересоздаются.
   - «Тонкая настройка» (шестерёнка): экземпляр, порт, шифрование, тайм-ауты, имена таблиц и столбцов, миграции, поисковая проекция. Для локального сервера транспорт не шифруется (соединение не выходит за пределы компьютера, проверка сертификата не отключается); для сетевого сервера шифрование включается автоматически.
3. **Администрирование → LLM**: провайдер, API-ключ (если нужен) и модель — щелчок по полю раскрывает список моделей, доступных ключу; вверху раскрытого списка — поиск по названию и ID; модели, которой нет в списке, можно задать ID кнопкой «Использовать … как ID модели» → «Сохранить». Для OpenRouter подставлена проверенная модель `openai/gpt-4.1-mini`. Первый сохранённый профиль сразу используется для обработки. Адрес API, ограничения запросов, заголовки и тарифы — в «Тонкой настройке». «Тест извлечения» на синтетических данных проверяет модель и определяет режим структурированного ответа.
4. **Обработка**: выберите папку → «Сканировать» → отметьте файлы → «Обработка». Перед запуском показывается оценка числа запросов, токенов и времени.
5. **Поиск**: введите фамилию, телефон, номер счёта, имя или код файла; щелчок по строке открывает карточку со всеми полями и фактами, включая JSON-поле ALL.

Где хранятся данные:

| Что | Где |
|---|---|
| Общие настройки (без секретов) | `%ProgramData%\FAKT\settings.json` (доступ ограничен ACL) |
| Ключи API и пароль SQL | зашифрованы DPAPI: `%LOCALAPPDATA%\FAKT\secrets` (для пользователя) или `%ProgramData%\FAKT\secrets` (для компьютера, ACL) |
| Журнал | `%LOCALAPPDATA%\FAKT\logs\fakt-ГГГГММДД.jsonl` (без ключей, паролей, полных телефонов и счетов, текстов записей) |

Переносной режим: `FAKT.exe --config-dir D:\FAKT-data` — настройки, секреты и журнал хранятся в указанной папке.

## 6. Безопасность

- Ключи API и пароль SQL хранятся только в защищённом хранилище Windows (DPAPI), не попадают в файл настроек, журнал, экспорт задания и командную строку worker.
- Ключ API привязан к адресу провайдера (схема, хост, порт): при смене адреса он не отправляется на новый адрес и удаляется при сохранении; ключ для `https` не уходит на `http`. Пароль SQL привязан к серверу и имени входа.
- Проверка сертификатов не отключается (кроме явно подтверждённого исключения для тестового SQL Server).
- Содержимое файлов — данные, а не инструкции: модель не выполняет код, ответы проверяются по схеме и по тексту записи; лица и факты, которых нет в записи, отбрасываются.
- Исходные файлы не изменяются и не удаляются.
- Подробную диагностику (с сырыми ответами модели) администратор включает на ограниченный срок; она пишется в отдельный журнал `fakt-verbose-*.jsonl`.

## 7. Сборка из исходников

Нужны .NET SDK 8+ (см. `global.json`) и, для сборки worker, любой Python 3.8+ с pip.

```powershell
# worker: Python 3.8.10 embeddable + закреплённые колёса (проверка MD5/SHA-256)
powershell -File worker\build\Build-Worker.ps1
# выпуск: dist\FAKT, архив zip, установщик (если установлен Inno Setup 6)
powershell -File build\Build-Release.ps1 -RunTests
```

Сборка без сети: положите `python-3.8.10-embed-amd64.zip` в `worker\build\cache`, скачайте колёса заранее (`pip download … -d wheelhouse`, команда — в справке `Build-Worker.ps1`) и укажите `-Wheelhouse <папка>`.

Тесты:

```powershell
dotnet test tests\Fakt.UnitTests                                          # модульные
dotnet test tests\Fakt.IntegrationTests --filter "Category!=RealLlm"      # SQL Server (localhost или FAKT_TEST_SQL_SERVER)
worker\build\out\python\python.exe -I -X utf8 worker\build\run_tests.py   # worker на поставляемом Python
```

Реальный интеграционный тест LLM запускается только явно — переменными окружения `FAKT_REAL_LLM_PROVIDER`, `FAKT_REAL_LLM_MODEL`, при необходимости `FAKT_REAL_LLM_KEY` (ключ — только через окружение):

```powershell
dotnet test tests\Fakt.IntegrationTests --filter "Category=RealLlm"
```

## 8. Устранение неполадок

| Симптом | Причина и решение |
|---|---|
| «Ошибка защищённого соединения с SQL Server (TLS/сертификат)» | На Windows 7 не включён TLS 1.2 (п. 2.6) или сертификат сервера не доверенный (п. 4.2). |
| «База данных «…» не найдена, и создать её не удалось» | У учётной записи нет права `CREATE DATABASE`: создайте базу вручную или выдайте роль `dbcreator`. |
| «Full-Text Search не установлен» | Установите компонент Full-Text Search на сервер; до этого работает только медленный режим поиска «Подстрока». |
| Worker не запускается на Windows 7 | Не установлены Universal CRT (KB2999226) и KB2533623. |
| «Возможности модели не подтверждены» | Выполните «Тест извлечения» в «Администрирование → LLM» (роль «Администратор»). |
| Локальная модель отвечает очень медленно | Модель не помещается в видеопамять целиком — выберите модель меньшего размера (например, 7–14B для 16 ГБ). |
