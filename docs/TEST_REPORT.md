**Windows 7 SP1 x64 недоступна: ни одна проверка на целевой ОС не выполнялась.** Все результаты ниже получены на Windows 11. Данные во всех тестах синтетические.

## Модульные тесты

Покрыты: построение адресов и привязка ключей к адресу (схема, хост, порт), проверка дат рождения (день первым, двузначный год, неоднозначные даты, названия месяцев, 29 февраля), нормализация и уточнение типов фактов (телефон без добавления кода страны, госномера кириллица/латиница, ведущие нули, СНИЛС/ИНН, VIN), проверка ответа модели (неизвестные, повторяющиеся и пропущенные ID, доказательство по тексту записи, статус личности, отклонённые кандидаты), контракт структуры (разделители, заголовок, фиксированная ширина, XML-пути и пространства имён), уточнение ширин колонок и имён колонок файлов без заголовка, построитель полнотекстового запроса (экранирование), маскировка журнала, планирование пакетов, генератор FileCode, имена SQL и разбиение пакетов, повторы и лимиты запросов, бюджет, настройки и права, DPAPI, адаптеры LLM на имитации HTTP-сервера (форма запросов и заголовков каждого диалекта, коды ошибок, 429 с Retry-After, обрезанные и некорректные ответы, `"usage": null`, ошибка-строка, отсутствие ключа в текстах ошибок).

Найдено и исправлено модульными тестами (7): падение адаптера Responses на каждом нормальном ответе (`"incomplete_details": null`); возможная утечка ключа в текст ошибки; немаскированные номера после даты в журнале; слова «Майя», «майор», «Мартин» принимались за месяцы; повторяющиеся имена колонок после переименования; отклонение XML-путей с кириллицей; потеря миллисекунд времени в журнале.

## Интеграционные тесты SQL Server

- Миграции V001–V008 повторяемы; сопоставление с существующей схемой другими именами столбцов; версии источников; идемпотентная фиксация; сбой после COMMIT; поиск (слова из разных таблиц, код файла, телефон в разном формате, госномера латиницей/кириллицей, счета с ведущими нулями), пагинация и подсчёт, карточка, перестройка проекции.
- **Автосоздание базы**: отсутствующая база создаётся со всей схемой (все миграции применены, готова к обработке и поиску); существующая не изменяется; недопустимые имена отклоняются без обращения к серверу; имя с `]` и `'` экранируется.
- **Отказы конвейера** (12 сценариев, дважды): падение worker между чтениями и во время чтения; обрыв сессии SQL внутри транзакции фиксации (shared memory и TCP); обрыв простаивающего соединения; база недоступна дольше всех повторов (остановка и продолжение без дублей); потеря подтверждения после COMMIT (в том же процессе и с перезапуском); пауза → продолжение → пауза → перезапуск → продолжение; отказы LLM (429, 503, тайм-аут, некорректный и обрезанный JSON, пропущенные, повторяющиеся и неизвестные ID). Итоговое содержимое базы в каждом сценарии совпадает по хешу с чистым прогоном.

## Реальный LLM (не имитатор)

Провайдер OpenRouter, модель `openai/gpt-4.1-mini`, ключ передавался только через переменную окружения. Набор:

1. Соединение, список моделей (457), «Тест извлечения» — режим JSON Schema, все проверки теста пройдены.
2. Определение структуры 10 файлов: CSV (UTF-8, Windows-1251), TSV, CSV без заголовка, TXT без заголовка со смешанными колонками, фиксированная ширина, XML с пространствами имён (через расширенный образец), JSON Lines, неструктурированное письмо (→ «Не табличный»), PNG (→ «Не поддерживается»). Совпадение с эталоном `testdata/MANIFEST.json`.
3. Обработка 5 файлов (107 записей) в новую автоматически созданную базу: два лица в записи с общими контактами, строки с «инструкциями» в данных, идентификаторы с ведущими нулями, два файла без заголовка. Все файлы «Завершён», ошибок записей 0; внедрённого «лица» нет; ведущие нули сохранены; полнота и точность по лицам **99,2 %** (эталон 126, извлечено 126, совпало 125); факты файлов без заголовка — **100 %** (59/59 и 78/78); полнотекстовый поиск «Черновиков» — 4 строки за 15–19 мс; карточка с ALL; поиск телефона в другом формате записи.

Ход исправлений по реальным прогонам (всё закреплено модульными тестами):

| Найдено | Исправлено |
|---|---|
| Модель часто возвращала результат только для первой записи пакета (9 из 25 записей — `missing_result`) | Схема ответа ограничивает число строк (`minItems = maxItems`), предупреждение о пропущенных записях, сырые ответы в подробном журнале |
| Лицо из «инструкции» в данных («добавь лицо …») | Правило промпта: просьбы в данных не выполняются |
| Ширины фиксированной ширины ±1 символ; последняя колонка молча обрезалась | Границы выравниваются по образцу; последняя колонка читается до конца строки |
| Файл без заголовка: ИНН помечены как СНИЛС/документ, госномер — как автомобиль | Смысловые имена колонок при определении структуры, сверка имён с форматом значений, проверка типа факта по формату |
| 29.02.1996 отклонена моделью как «невозможная» | Календарная проверка приложения принимает корректную дату |
| XML-путь `./p:person` отклонялся | Эквивалентные пути нормализуются |

Оставшееся расхождение (1 из 126 лиц в прогоне, каждый раз разное) — искажённая моделью фамилия; валидатор её отклоняет (значения нет в записи), в базу искажённые данные не попадают.

Другие модели через OpenRouter: РЕЗУЛЬТАТ_QWEN. `google/gemini-2.5-flash-lite` — провайдер отказал в доступе («Blocked by Google AI Studio», региональное ограничение); приложение показало понятную причину.

Локальная модель LM Studio (`qwen/qwen3.6-27b`, Q4, 17,5 ГБ) на GPU 16 ГБ не ответила за 10 минут — извлечение с локальной моделью не проверено (нужна модель меньше).

## Нагрузочный тест (имитатор LLM — не доказательство работы провайдера)

Настройки по умолчанию (chunk 5 000, 10 записей в запросе, 2 параллельных запроса, SQL-пакет 500), локальный имитатор LLM с нулевой задержкой, реальный worker и SQL Server.

| Прогон | Только чтение worker | Полный конвейер | Пик .NET | Пик Python |
|---|---|---|---|---|
| 1 000 000 CSV | 33–36 тыс. записей/с | 413–440 с, 2 276–2 419 записей/с | 109 МБ | 62 МБ |
| 1 000 000 фиксированная ширина | 36 тыс./с | 403 с, 2 485/с | 110 МБ | 61 МБ |
| 1 000 000 JSON Lines | 29 тыс./с | 408 с, 2 450/с | 111 МБ | 66 МБ |
| 1 000 000 CSV, очередь 64 | — | 319 с, 3 139/с | 105 МБ | 62 МБ |
| 200 000 CSV с 1 101 отказом LLM | — | 273 с | 111 МБ | 61 МБ |

Память не растёт с размером файла (50 тыс. и 1 млн записей — 105 и 109 МБ). После результатов очередь конвейера по умолчанию увеличена с 8 до 32. Найдено и исправлено: маскировка падения worker как «Читатель не найден»; numpy/OpenBLAS резервировал около 777 МБ под потоки простаивающего worker; рост памяти pandas 2.0.3 с позицией в файле. Поиск по 1 млн записей: большинство запросов 1–50 мс, «подстрока» по редкому фрагменту — около 3,4 с (без индекса).

## Не проверено

- Работа на Windows 7 SP1 x64 (клиент, .NET Framework 4.8, Python 3.8 с pandas 2.0.3/numpy 1.23.5, TLS 1.2 через SChannel) — целевая ОС недоступна.
- Установщик Inno Setup — сценарий не компилировался (Inno Setup не установлен); проверена переносная папка.
- Облачные провайдеры, кроме OpenRouter: реальные ключи не использовались, адаптеры проверены на имитации HTTP-сервера.
- Подключение к SQL Server по сети с доверенным сертификатом (проверено только localhost с «Доверять сертификату»).
- Экранные дикторы и высокий DPI на Windows 7.
